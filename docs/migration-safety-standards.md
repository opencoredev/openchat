# Migration Safety Standards

These standards apply to every Convex migration in `apps/server/convex/migrations.ts` and `apps/server/convex/migrations/*.ts`.

## Required Guarantees

- Idempotent: repeated runs produce the same final data state.
- Typed: migration args and return values must be validator-backed.
- Dry-run capable: every destructive or bulk migration must support `dryRun`.
- Verify-first: each migration family must expose at least one verification function.
- Reportable: migration execution must emit a machine-readable report.

## Required Lifecycle (Per Migration)

1. Pre-check
   - Validate assumptions (indexes exist, table shape is compatible, env prerequisites).
   - Refuse to run with unsafe parameters.
2. Apply
   - Batch writes.
   - Keep operation restart-safe.
3. Verify
   - Confirm postconditions (counts, referential integrity, field presence).
   - Include sample mismatches in response payload.
4. Rollback Strategy
   - Document whether rollback is full, partial, or non-reversible.
   - If non-reversible, include compensating forward migration plan.

## Command Contract

- Run migrations: `bun run convex:migrate`
- Verify only: `bun run convex:verify`
- JSON report: `bun ./scripts/run-migrations.ts --report <report-path>.json`

## Report Format

The report generated by `scripts/run-migrations.ts` must include:

- run metadata: timestamp, mode, force flag
- migration results: per migration status and details
- verification result
- summary: successful, failed, skipped counts
- rollback strategy map for every migration entry

## Review Checklist (Required in PR)

- [ ] Migration args and return shape validated.
- [ ] Dry-run path tested and included in PR notes.
- [ ] Verification command run with result attached.
- [ ] Rollback/compensation strategy documented.
- [ ] No `as any` / `as unknown as` introduced in runtime paths.
